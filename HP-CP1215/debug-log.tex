\section{The tools, from the ground up}
%=====================================================================

Before any debugging, here is what every name in this story means. Your printer sits at the bottom of a stack of programs written by five different parties, and the colours below are used throughout.

\subsection{Words you need first}

Every term below is used later without further explanation, so this list comes first. Read it once, then come back to it whenever a word is unclear.

\begin{flowtext}
\term{PostScript (PS)} An older page format: a small program that, when run, draws the page (text, shapes, images). Many office printers can run it themselves; on a Mac it is mostly an in-between step.
\term{Driver} Software that translates what an app sends into the language one particular printer understands.
\term{CUPS} \emph{Common Unix Printing System}: the part of macOS that manages printing. Apple maintains it as open source and Linux uses it too. Every print job goes through it.
\term{Queue, job} A \emph{queue} is CUPS's named in-tray for one printer (ours: \texttt{HP\_Color\_LaserJet\_CP1215}). A \emph{job} is one thing sent to print; jobs are numbered (155, 156, 157 later in this story).
\term{Filter} A small converter program in CUPS's chain. It takes the job in one format and outputs it in another, for example PDF in, PostScript out. CUPS runs several filters one after another.
\term{Backend} The last link of the chain: the program that delivers the finished bytes to the printer, here over the USB cable.
\term{PPD} \emph{PostScript Printer Description}: a plain-text file that describes one printer to CUPS: which paper sizes it takes, whether it prints colour, and which filter to use for which kind of input. Every queue has its own copy.
\term{Wrapper} A shell script whose job is to run other programs in the right order with the right settings.
\end{flowtext}

\subsection{Commands and symbols you will see}

\begin{flowtext}
\cmd{\texttt{gs}} is Ghostscript.
\cmd{\texttt{lp}} sends a file to a print queue. \texttt{-d} names the queue; \texttt{-o raw} means ``send as is, run no filters''.
\cmd{\texttt{lpstat}} shows the state of printers and jobs.
\cmd{\texttt{cupsctl}, \texttt{cupsfilter}} \texttt{cupsctl} changes CUPS settings (here: debug logging); \texttt{cupsfilter} runs a queue's filter chain into a file without printing.
\cmd{\texttt{identify}} is ImageMagick's command that reports an image's size. ImageMagick is a toolkit for handling images.
\cmd{\texttt{strings}, \texttt{xxd}} show the readable text inside a file; show its raw bytes in hexadecimal.
\cmd{\texttt{killall}} stops a running program by name.
\par\medskip\noindent\textit{Symbols that glue commands together:}
\cmd{\texttt{>}, \texttt{>>}} write a command's output into a file, replacing it or adding to it.
\cmd{\texttt{2>\&1}, \texttt{2>/dev/null}} Error messages travel on their own channel (``stderr''). \texttt{2>\&1} merges them into the normal output; \texttt{/dev/null} is the computer's black hole: anything sent there is thrown away.
\cmd{\texttt{\&\&}, \texttt{;}} run the next command only if the previous one succeeded (\texttt{\&\&}), or in any case (\texttt{;}).
\cmd{\texttt{echo "exit=\$?"}} prints the previous command's \emph{exit code}: a number every program leaves behind when it ends, \texttt{0} meaning success and anything else failure.\end{flowtext}

\subsection{The printer and its language}

Most office printers are \emph{smart}: they contain a small computer and software that can read PDF or PostScript, so the printer itself does the rendering and you just send it the page. The \textbf{HP Color LaserJet CP1215} is not like that. It is a \emph{host-based} printer (also called a ``software'' or ``GDI'' printer): HP left the small computer out to make it cheaper, so \emph{the computer you print from}, the ``host'', has to do the rendering and send the finished bitmap in HP's own compressed binary format, \textbf{ZjStream} (ZjStream files start with the four letters \texttt{JZJZ}). HP shipped Windows software that does this; it never shipped a macOS driver. Everything below exists to turn a PDF into ZjStream on a Mac.

\subsection{The cast}

\begin{flowtext}
\piece{cApple!45}{CUPS}{Apple, open source} \emph{Common Unix Printing System}, the printing system of macOS (defined above). Every print job, from ⌘P or from the terminal, goes into a CUPS queue; CUPS runs its chain of filters on the job, then the backend delivers the bytes (here, USB).
\piece{cApple!45}{PPD}{generated per printer} \emph{PostScript Printer Description}: a plain-text file per queue that describes the printer (paper sizes, colour, duplex) and tells CUPS \emph{which filter program} to use for which input format. Ours is \texttt{/etc/cups/ppd/HP\_Color\_LaserJet\_CP1215.ppd} (shown in section~\ref{sec:ppd}).
\piece{cApple!45}{cgpdftopdf}{Apple} A CUPS filter that takes a PDF and hands on a PDF. It exists to apply the print dialog's choices to the document itself (which pages, how many per sheet, rotation) before the next filter sees it. For our jobs there was nothing to apply: its log line says ``NO filtering is needed; passing data through''.
\piece{cApple!45}{cgpdftops}{Apple} A CUPS filter that turns PDF into PostScript.
\piece{cOP!60}{foomatic-rip}{OpenPrinting, 2011, v4.0.6} A generic adapter filter (``Foomatic'' is OpenPrinting's collection of printer-driver descriptions; ``rip'' stands for \emph{raster image processor}, the old name for a program that renders pages). It reads the PPD, finds the command line written there for this printer, and runs it. In our PPD that is the line \texttt{*FoomaticRIPCommandLine: "foo2hp2600-wrapper \%A"} (section~\ref{sec:ppd}), so it runs \texttt{foo2hp2600-wrapper}.
\piece{cRick!60}{foo2zjs, the package}{Rick Richardson} A collection of open-source drivers for host-based printers, named after its first driver, which spoke ZjStream (``zjs''). It contains, among others:
\subpiece{cRick!60}{foo2hp2600-wrapper}{Rick Richardson} A shell script: feeds the page through Ghostscript, then through \texttt{foo2hp}.
\subpiece{cRick!60}{foo2hp}{Rick Richardson} Turns a bitmap into ZjStream for the family of HP colour laser printers that includes the CP1215. Written from scratch by Rick. Compression uses Markus Kuhn's JBIG-KIT library (JBIG is a method of compressing black-and-white images).
\piece{cGS!60}{Ghostscript, \texttt{gs}}{Artifex} Renders PostScript or PDF into bitmaps. The wrapper calls it.
\piece{cPharos!80}{paagent}{Pharos, installed for NYU printers} Print-management software that NYU installs to track and bill campus printing. Its \texttt{paagent} is a backend that sits in front of every queue on AlfMAC3; for this printer it only passes the bytes through to USB.
\piece{cYou!80}{print.py}{you} Your front end, built with Tkinter. It skips CUPS's filters (section~\ref{sec:script}).
\piece{grey!60}{Homebrew}{community} The package manager. It keeps each program in its own folder under \texttt{/usr/local/Cellar} and \emph{links} it into \texttt{/usr/local/bin}, the folder where the shell looks for them, so that a command like \texttt{gs} works.
\end{flowtext}

Source for foo2zjs: Rick Richardson's site, now offline; snapshot at \url{https://web.archive.org/web/20210129024712/https://foo2zjs.rkkda.com/}. A maintained copy lives at \url{https://github.com/OpenPrinting/foo2zjs}.

\subsection{The chain, as a picture}\label{sec:chain}

Every page has to go \textbf{PDF $\rightarrow$ PostScript $\rightarrow$ bitmap $\rightarrow$ ZjStream $\rightarrow$ USB}. This is the chain CUPS ran for a ⌘P print job on AlfMAC3 before the fix. It is drawn here up front, but it comes from evidence found later: the CUPS log of job 156 (section~\ref{sec:decisive}) and the PPD (section~\ref{sec:ppd}).

Left to right: the app hands CUPS a PDF. Apple's \texttt{cgpdftopdf} passes it through unchanged. \texttt{foomatic-rip} reads the PPD, turns the PDF into PostScript with a conversion step of its own, and runs the command the PPD names for this printer: Rick's wrapper. The wrapper has Ghostscript render the PostScript into a bitmap, and \texttt{foo2hp} turn the bitmap into ZjStream. Pharos's \texttt{paagent} passes the bytes on, and they leave over USB.

\begin{insight}{Finding the chain yourself}
\begin{itemize}[nosep]
  \item \textbf{The PPD.} Its \texttt{*cupsFilter} lines say which filter takes which kind of input (section~\ref{sec:ppd}); its \texttt{*FoomaticRIPCommandLine} names the wrapper.
  \item \textbf{CUPS's own log, with debug logging on} (\texttt{sudo cupsctl --debug-logging}, section~\ref{sec:debug}). For each job it writes a \texttt{Started filter} line per link of the chain. This is where the chain above was read from.
  \item \texttt{cupsfilter --list-filters} prints the filters CUPS would use without running them. On AlfMAC3, though, \texttt{cupsfilter} picked a different chain from the real queue (section~\ref{sec:ppd}), so the log is the one to trust.
\end{itemize}
\end{insight}

\subsection{First look: test everything that does not print}

I proposed testing every link of the chain up to the printer without printing (it was past 1:50 in Italy). The links are the ones in section~\ref{sec:chain}, and each can be checked on its own: make a PDF, run the wrapper on it and look at what comes out; ask CUPS about the queue, its settings and the device it sends to; and read CUPS's log. These commands all went out in one SSH call.

First, a one-page test PDF made with Ghostscript:

\begin{mine}
cd /tmp
gs -q -sDEVICE=pdfwrite -sPAPERSIZE=a4 -o /tmp/t.pdf -c "/Helvetica findfont 40 scalefont setfont 100 400 moveto (Test) show showpage" 2>&1 | tail -3
\end{mine}
\begin{cmdout}
GPL Ghostscript 9.27: Can't find initialization file gs_init.ps.
\end{cmdout}

\begin{insight}{How that line draws a test page}
Ghostscript reads \emph{PostScript}, a programming language for drawing pages, and \texttt{-c} hands it a few words of it directly instead of a file. PostScript works like a stack calculator: values first, then the operation that uses them.
\begin{itemize}[nosep]
  \item \texttt{/Helvetica findfont 40 scalefont setfont}: pick the Helvetica font, at 40 points.
  \item \texttt{100 400 moveto}: move the pen to 100 points from the left, 400 from the bottom.
  \item \texttt{(Test) show}: write the text ``Test'' there.
  \item \texttt{showpage}: the page is finished; output it.
\end{itemize}
The rest is Ghostscript's own: \texttt{-sDEVICE=pdfwrite} chooses PDF as the output, \texttt{-sPAPERSIZE=a4} the page size, \texttt{-o /tmp/t.pdf} the output file, \texttt{-q} quiet. \texttt{2>\&1 | tail -3} keeps the last three lines of anything it prints, errors included.
\end{insight}

Here Ghostscript cannot even start: \texttt{gs\_init.ps} is the file it loads before doing anything. So there is no test PDF. Next, the wrapper on that PDF (its options are explained in section~\ref{sec:script}), then the size and the first bytes of what it wrote. \texttt{ls -la} lists in long form (\texttt{-l}: permissions, owner, size in bytes, date), including hidden files (\texttt{-a}); \texttt{head -c 64} keeps the first 64 \emph{bytes} (\texttt{-c}), not lines; \texttt{xxd} shows them in hexadecimal.

\begin{insight}{Device addresses}
CUPS names every place it can send a job with an address shaped like a web URL, a \emph{device URI}. \subsection{Restarting CUPS}

CUPS reads the PPD when it starts, so it has to restart. \texttt{launchctl} controls macOS's background services; \texttt{kickstart -k} restarts one, stopping it first.

\begin{pane}
sudo launchctl kickstart -k system/org.cups.cupsd && sleep 2 && lpstat -p HP_Color_LaserJet_CP1215
\end{pane}
\begin{cmdout}
Could not kickstart service "org.cups.cupsd": 1: Operation not permitted
\end{cmdout}

System Integrity Protection (SIP, a macOS safeguard that stops even administrators from changing parts of the system) forbids restarting a built-in service that way. Stopping it works (\texttt{killall} stops a program by name); macOS relaunches it on the next request:

\begin{pane}
sudo killall cupsd; sleep 2; lpstat -p HP_Color_LaserJet_CP1215
\end{pane}
\begin{cmdout}
printer HP_Color_LaserJet_CP1215 is idle.  enabled since Sun 11 Oct 02:11:18 2026
\end{cmdout}

\section{Summary}

\begin{flowtext}
\par\noindent\bugemo\ \textbf{Bug 1: Ghostscript.} \textbf{Broke:} both routes on AlfMAC3. \textbf{Symptom:} an empty \texttt{.prn}, so 0 bytes printed. \textbf{Cause:} \texttt{/usr/local/bin/gs} was a 2019 Ghostscript 9.27 without its support files. \textbf{Evidence:} ``Can't find initialization file gs\_init.ps''. \textbf{Fix:} remove the root-owned 9.27 docs, then \texttt{brew link --overwrite ghostscript}. \textbf{Proof:} job 155, printed.

\par\noindent\bugemo\ \textbf{Bug 2: foomatic's PDF step.} \textbf{Broke:} ⌘P on AlfMAC3; most likely also why it stopped on AlfMAC and never worked on AlfMAC2. \textbf{Symptom:} the job ``completes'' but 0 bytes are sent. \textbf{Cause:} foomatic-rip 4.0.6 converts PDF with \texttt{pswrite}, which Ghostscript removed in 2013. \textbf{Evidence:} ``Unknown filetype'' and ``Unknown device: pswrite''. \textbf{Fix:} comment out the PDF \texttt{*cupsFilter} line in the PPD, and set the A4 defaults. \textbf{Proof:} job 157, 3088 bytes.
\end{flowtext}
